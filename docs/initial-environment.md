## 从中文到正式采集

运行下面的命令会从已登记的三个任务中生成任务清单及对应的官方场景。输出目录应为新的目录。

```bash
cd ~/by/genie_sim
.venv/bin/python request_finemanip.py \
  '生成手机装盒、盖笔帽和积木插入，每个任务5条，覆盖两个场景' \
  --repo genie_sim-main --output output/my-finemanip
```

同一个任务给两个场景分别分配 3 条和 2 条成功额度。以盖笔帽为例，两个实例对哪只手抓笔的要求互换。积木插入的两个实例也指定了不同执行手。保留官方实例指令和任务判定，避免入口改写动作约束。

| 任务 | 实例 0 目标 | 实例 1 目标 | 已验收轨迹 |
|---|---:|---:|---:|
| 手机装盒 | 3 | 2 | 0 |
| 盖笔帽 | 3 | 2 | 0 |
| 积木插入 | 3 | 2 | 0 |

论文的场景管线可以接进平台的任务入口。把中文解析成任务、场景和数量，再由任务执行器驱动机器人，并按接触结果和最终状态做成功判定。入口已能处理登记任务，批量轨迹采集尚未跑通。上游为 FineManip 提供了场景和评测规则，默认策略需要推理端点。若走脚本路线，需为三个任务各补一份适配 `G2_crsB_90D` 的采集程序，并使用上游 Collection 运行时采集同步的动作、状态和视频。每个场景的配额应以通过判定的有效回合累加。

服务器配有两张 A100。Isaac Kit 已启动，运行时兼容性检查器将两张卡标为 `supported`。NVIDIA 的 Isaac Sim 6.2 硬件要求仍列出 A100 为不支持机型。安装和测试独立于系统环境，服务端日志写入 `logs/isaac-install.log`、`logs/isaac-compat.log`、`logs/isaac-camera-lean.log` 和 `logs/isaac-camera-smoke.log`。相机测试通过后，服务器会尝试用原仓库渲染器输出六个场景的前、侧、俯视图，日志为 `logs/finemanip-isaac-layouts.log`。正式采集还需要完成任务执行和轨迹验收。
